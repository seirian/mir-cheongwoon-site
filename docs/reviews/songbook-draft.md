# 노래책 2차 검토안

## 범위
feature/songbook에서만 작업한다. main/develop 병합과 운영 릴리스 활성화는 하지 않는다.

## 변경
- 곡 목록, 상세, CSV, 검토실, 메타태그와 배포 JS에서 수집 출처를 제거한다. 별도 공개용 화이트리스트 모델을 빌드 전에 만든다. 기존 Git 이력을 재작성하지 않으며 이전 커밋의 자료를 새로 만든 것으로 주장하지 않는다. 출처 비표시는 이용 허락을 대신하지 않는다.
- 제목 오른쪽 작은 영상 아이콘은 안전성 검사한 첫 번째 영상으로 새 탭 이동한다. 다중 영상은 상세창에 있다.
- 카테고리는 체크박스 다중 선택(OR), 다른 필터와는 AND. 난이도 전체/1~5/미정 지원.
- 참고 난이도: 공개 노래책 5개, 47페이지의 명시적 난이도 항목을 비교했다. 모든 곡이 1로 동일한 두 자료는 초기값 가능성이 있어 제외했다. 곡명/원곡자/확인한 별칭이 일치하는 49곡만 서로 다른 노래책별 1표로 중앙값(0.5는 올림) 반영했다. 다른 가수의 숙련도를 난이도로 전용하지 않았다. 293곡은 아직 미정이다.
- 숙련도는 미르님 지정 owner 계정만 서버 저장한다. 일반 관리자와 manager는 곡 정보만 관리하며 숙련도 수정 불가. 자동 계정 지정은 하지 않았다.
- 곡 검색: 공식 iTunes Search API의 곡명/가수 메타데이터만 조회. 검색 결과 선택 또는 직접 입력, 카테고리 다중 지정, 영상/난이도 확인 후 저장한다. 기존 곡 중복은 편집으로 유도한다. 구 서비스의 로그인 관리자 화면은 검증하지 못했으며 비공개 기능 완전 복제를 주장하지 않는다.

## 저장/권한
Supabase에 신규 검토 전용 songbook_preview_editors, songbook_preview_entries, songbook_preview_ratings를 추가했다. 기존 운영 콘텐츠/배치는 변경하지 않았다. DB migrations: songbook_preview_v2_editor_and_ratings, songbook_preview_v2_validate_table_identity. 전체 스키마는 Supabase migration history에 저장되어 있다.

관리자: 노래책의 편집 로그인 → 미르님 편집 권한 연결 → 미르님 가입 계정 UUID 입력. 미르님은 본인의 계정 ID를 확인하여 전달하고 지정 후 다시 로그인한다. owner는 하나만 허용하며 기존 owner를 자동 교체하지 않는다. 관리자 신분은 기존 admins 테이블로 확인하고 사용자가 변경 가능한 metadata를 권한에 사용하지 않는다.

전용 Supabase 클라이언트는 기존 로그인과 다른 세션 키를 사용한다. 변경 요청은 신규 검토 테이블과 로그인/로그아웃만 허용한다. 서버 RLS가 실제 권한을 강제한다. 수정 시 revision을 비교해 동시 수정을 탐지하며 DB 트리거가 증가시킨다. 안전하지 않은 영상 URL과 범위 밖 별점은 DB에서도 거절한다.

`?demo=1`은 검토 빌드에서만 활성화되고 localStorage에만 저장한다. 실제 owner 숙련도와 명확히 구분한다.

## 검증
- 기존+신규 Node 테스트, Vite build, Python/PHP 문법.
- 1440/1024/768/390 화면, 다중 카테고리 URL/새로고침 유지, 1~5별 필터와 전체, 검색, 상세, 체험 숙련도 지속 및 새 노래 등록, 서버 변경 0회 브라우저 테스트.
- 실제 DB에서 임시 계정과 데이터로 owner 저장/수정/동시수정 버전, manager 숙련도 금지, 방문자/익명 쓰기 금지, 잘못된 별점/영상 거절, 다른 editor ID 조회 차단을 검증하고 전체 트랜잭션 rollback.
- 난이도 수집 상세와 원본은 배포하지 않는다. 과거 Git/1차 미리보기까지 자동 삭제하는 작업은 별도다.
