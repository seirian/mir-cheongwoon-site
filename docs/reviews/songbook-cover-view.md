# 노래책 목록형 / 커버형 · 1차 검토

## 목적과 범위
현재 운영 기준 `4b42ef36`에서 `feature/songbook-cover-view`로 분리한 검토안이다.
목록형을 기본으로 유지하고 탐색기의 보기 버튼처럼 목록형/커버형 두 버튼으로 선택한다.
커버형은 정사각형 이미지, 곡명, 가수, 모든 카테고리, 참고 난이도를 카드로 표시한다.
카드의 커버/곡명은 기존 곡 상세를 열며 영상·신청 문구·숙련도는 여기서 이용한다.
신청 상태와 즐겨찾기는 카드에도 유지하고, 기존 관리자에게는 카드 체크박스/빠른 수정도 연결한다.

## 완료 조건
- 최초 방문은 목록형. 선택은 전용 브라우저 저장소에 보관하며 URL layout 값이 있으면 우선한다.
- 기존 view(즐겨찾기/영상 유무) 조건과 layout을 혼합하지 않는다.
- 검색·필터·정렬·페이지 번호·페이지당 10/25/50/100(기본25)을 보기 전환으로 초기화하지 않는다.
- 현재 페이지의 관리자 선택은 보기 전환에서도 유지하고 실제 페이지/조건 변경에서는 기존대로 해제한다.
- 기존 앨범 이미지 우선, 없거나 실패하면 첫 YouTube 썸네일, 그마저 없거나 실패하면 음악 아이콘.
- 앨범 커버와 썸네일을 구분하며 기존 Apple Music 음원 연결 표기를 보존한다. 새 정보 수집은 없다.
- 모든 카테고리 보존. 긴 제목은 두 줄까지 보이며 상세/접근성 이름에서 전체를 확인한다.
- 카드 난이도는 difficulty, 숙련도는 상세에서 별도로 확인한다. 미정 값을 임의 평가하지 않는다.
- 모바일2열 및 넓이에 따른 다열 배치, 키보드 상세 열기와 닫기, 이미지 실패 대응.

## 검토와 운영 격리
별도 Vite 진입점은 운영 화면 컴포넌트를 재사용하되 검토 빌드에 한해서 데이터 저장소를 읽기 전용으로 교체한다.
운영 App/공통 인증·관리자 조회·쓰기 API는 로드하지 않는다. 편집/삭제/수집 패널은 검토 번들에서 제외한다.
운영의 현재 공개 목록과 삭제 상태를 읽어 만든 정적 사본이며 실제 가창·신청 상태를 변경하지 않는다.
이 검토 주소는 시청자 보기 방식 검토용이다. 관리자 커버 동작은 격리 인증/API 테스트로 검증한다.
운영의 즐겨찾기/보기 키와 다른 preview namespace를 사용한다. 공유 URL도 검토 릴리스 안에서만 생성한다.
별도 검토에서 변경한 보기 방식/즐겨찾기는 운영으로 이전되지 않는다. 사본은 실시간 동기화하지 않는다.

## 배포
기존 GitHub Actions/SFTP 호스트키 확인/새 릴리스 업로드를 사용한다.
새 workflow는 `feature/songbook-cover-view`만 허용하고 새 정적 디렉터리를 stage만 한다.
운영 라우팅 전후 해시를 확인하며 main/develop/backup_20261007 및 DB·권한·키·스케줄은 변경하지 않는다.

## 검증
단위검사: 기본값/명시URL/저장소차단/페이지·필터동일성/이미지후보/격리 설정.
브라우저: 목록·커버 동일 데이터, 정렬/페이지 유지, 10/25/50/100, 즐겨찾기 공유, 상세/복사, 반응형,
누락/실패 커버, 긴 복수 카테고리, 저장소 차단. 공개 검토에서는 실제 이미지도 확인한다.
운영 경로의 관리자 검사는 기존 모의 인증/API에서 선택 유지/확인창취소/빠른수정 진입/권한회수를 검사한다.
최종 실제 실행 결과와 주소는 검토 PR에 기록한다. 운영 데이터 변경은 테스트 수단으로 사용하지 않는다.
