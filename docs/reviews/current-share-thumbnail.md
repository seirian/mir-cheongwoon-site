# 현재 홈 화면 공유 썸네일

## 원인과 범위
네이버 카페에 도메인을 붙였을 때 보이는 카드는 실제 페이지 스크린샷을 자동 캡처하는 기능이 아니다. 사이트의 초기 HTML `og:image`가 빌드에 복사된 예전 `og/home.png`를 가리키고 있었다. 관리자 홈 이미지와 이 정적 썸네일은 별개였다.

운영 배포에서 최신 후보 빌드와 현재 공개 저장 이미지를 사용해 홈 상단 화면을 캡처하고 1200×630 PNG로 `dist/og/home.png`를 교체한다. 현재 헤드의 og:image/twitter:image 절대 주소는 그대로 해당 **새 릴리스 경로**를 사용한다. React 실행 전의 원본 HTML에서도 유효하므로 수집기가 JavaScript를 실행할 필요가 없다.

## 안전 및 디자인
- 실제 사이트의 React/CSS/모바일·PC 화면/이미지 업로드/일정표 코드는 변경하지 않는다.
- 별도 익명 Chromium과 127.0.0.1 정적 서버로 후보 빌드만 캡처한다. 계정·DB·Storage 쓰기·인증은 금지한다.
- 저장 이미지 조회와 실제 이미지 로드 완료를 확인한다. 오류를 미등록으로 간주해 예전 기본 썸네일을 배포하지 않는다. 생성 실패 시 활성화 전에 배포를 중단한다.
- 시간에 따라 달라지는 방송 상태만 캡처 브라우저에서 숨긴다. 실제 사이트에는 영향을 주지 않는다.
- 배율/비율을 유지하고 안전 여백을 넣어 이미지나 글자를 잘라내지 않는다. BLUED 전용 썸네일과 나머지 빌드 파일은 바이트 변경이 없어야 한다.
- 비밀값 없이 캡처 이미지, 원본 캡처, 해시·원본 URL·검증 결과를 artifact로 남긴다.

## 검증
실제 빌드를 사용하는 격리 CI에서 저장/미등록/조회 실패/다운로드 실패/잘못된 base를 검사한다. 배포 후 /, 공유 쿼리 주소, /schedule, BLUED 원본 HTML 및 이미지의 HTTP·PNG 크기·배포 이미지 해시를 확인한다.

## 캐시와 갱신 범위
이 기능은 **운영 배포 시점의 스냅샷**이다. 관리자 이미지 교체만으로 외부 카드가 즉시 갱신되는 기능은 아니다. 이후 배포/수동 재배포 시 새로 캡처한다. 저장 파일·DB 스키마를 바꾸지 않는다.
네이버가 이미 삽입하거나 캐시한 카드를 사이트 배포만으로 강제 교체할 수 있다고 보장하지 않는다. 작성 중인 카드는 지우고 다시 삽입하고, 필요하면 `/?share=<새 릴리스 커밋 앞 8자리>`로 새 카드 생성을 시도한다. 쿼리는 같은 홈으로 연결되며 canonical은 기본 도메인으로 유지한다. 네이버 카페의 캐시 갱신 시간·실제 로그인 편집 화면 검증은 별도이다.
