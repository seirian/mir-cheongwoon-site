# 노래책 사용성 1차 검토

## 목적 / 완료 조건
사용자가 승인한 다섯 항목(신청 상태 표시·필터, 목록 문구/곡 링크 복사, 검색 중심 모바일, 대표 영상·용도, 관리자 빠른 수정)을 feature/songbook_check에서 독립 구현한다. develop/main에 병합하지 않는다. 실제 클릭·저장 가능한 검토 주소를 기존 GitHub Actions/SFTP 릴리스 경로에 배포하되 운영 릴리스는 활성화하지 않는다.

## 구조와 데이터
별도 songbook-check.html / vite.songbook-check.config.js 진입점을 사용한다. 운영 App/AuthProvider/songbookStore는 로드하지 않는다. 공통 URL 검증, 곡 검색·정렬, 가창 링크 병합·삭제 제외, 10초 안내 훅만 재사용한다. 공개 읽기 권한으로 목록 사본을 빌드 시 생성하며 신청 상태·난이도·숙련도를 임의 변경하지 않는다. 작성자·출처·개인 검토 내역은 가져오지 않는다. 별도의 6곡 샘플은 예시라고 표시한다.

편집/즐겨찾기는 mir-songbook-check-v1:sample 또는 :snapshot localStorage만 사용한다. 관리자 체험은 실제 관리자 인증이 아니라 검토 화면 전환이다. API 변경·키 재설정·DB/계정 권한·노래 추가/삭제·자동 수집/스케줄 변경은 없다. 사본은 시점이 표시되며 실시간 운영 목록이 아니다. 공유 링크도 검토 릴리스에 한정되며 필터/관리자 모드/로컬 편집 내용은 공유되지 않는다. 직접 신청 접수나 채팅 전송을 제공하지 않는다.

## 배포
기존 .github/workflows/songbook-platform-preview.yml의 Node24/검증/브라우저/공개 설정/SFTP stage-only 흐름을 사용한다. 새 브랜치는 기존 워크플로의 실행 대상이 아니므로 전용 songbook-check-preview.yml에서 실행한다. 기존 yeop_deploy_ci.Remote의 호스트키 확인/소유권/새 파일만 쓰기/SFTP read-back을 재사용한다. /web/_mir_site/_yeop_releases/새 릴리스 아래만 작성하고 운영 .htaccess 둘의 지문을 전후 대조한다. 새 릴리스 자체의 .htaccess 외 운영 라우팅은 변경하지 않는다. PHP/API/비밀 설정 파일은 배포하지 않는다.

## 검증 계획
npm run verify, npm run check:backend, 신규 12개 단위 검사. GitHub Actions에서 5개 해상도의 시청자/관리자 화면, 신청 상태/복사/필터, 대표 지정, 저장 후 다음 곡, 새로고침, 미저장 확인, 저장 실패, 초기화 격리, 공개 사본과 네트워크 변경 0건을 검사한다. 실행 결과와 검토 URL은 PR에 기록한다. 이 컨테이너의 Chromium 로컬 URL 접근은 ERR_BLOCKED_BY_ADMINISTRATOR로 차단돼 해당 제한을 변경하지 않고 기존 CI에서 브라우저 검증한다. 운영 사용자 곡에 시험 쓰기를 하지 않는다.

## 범위 구분
기존 운영의 전체 곡 편집/외부 음악 검색/자동 수집 확인/삭제·복원은 새 검토 화면에 중복 구현하지 않는다. 기존 코드는 그대로 남는다. 실제 도입 시 새 대표 영상/공개 안내의 저장 규칙과 기존 관리자 권한 연결은 검토 승인 후 별도로 통합한다. 신청 상태를 일괄로 바꾸거나 가창 횟수로 숙련도를 자동 부여하지 않는다.
