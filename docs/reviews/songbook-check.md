# 노래책 사용성 2차 검토

## 요청 / 완료 조건
feature/songbook_check에서 1차 검토안의 신청 상태·복사/공유·모바일·빠른 수정은 유지하고, 곡별 카테고리 표시를 복원하며 첫 번째 YouTube 링크를 대표 영상으로 자동 지정한다. develop/main 및 운영에는 병합하지 않는다. 기존 GitHub Actions로 새 검토 릴리스만 배포한다.

## 2차 변경
- 곡명·가수 바로 아래에 원래 카테고리를 모두 배지로 표시한다. 상세창과 빠른 수정에서도 같은 컴포넌트를 사용한다. 카테고리 값·순서를 바꾸거나 선택한 검색 조건 하나로 축소하지 않는다. 모바일에서도 생략하지 않고 줄바꿈한다.
- 대표 영상은 정규화된 연결 영상 배열에서 처음 나오는 유효한 YouTube URL로 계산한다. SOOP이 배열 앞에 있어도 첫 YouTube를 찾고, 영상 순서·시간값은 그대로 유지한다. 별도 대표 지정 클릭/저장이 필요하지 않다.
- 첫 YouTube 제거 시 다음 YouTube를 사용한다. 모든 YouTube를 제거하면 대표는 미지정이며 SOOP 링크는 보존한다. 새 YouTube를 연결하면 즉시 같은 기준으로 다시 표시한다. 여러 YouTube 중 나중에 추가한 링크가 첫 링크를 덮어쓰지는 않는다.
- 대표는 이번 요청의 자동 규칙으로 통일한다. 1차 검토에서 저장한 수동 대표 값은 대표 계산의 근거로 사용하지 않는다. 기존 브라우저 검토 데이터의 가수·신청 상태·공개 안내·영상 용도는 보존하고, 조회만으로 localStorage를 다시 쓰지 않는다. 대표 표시와 관리자 미지정 작업 목록에 같은 값을 사용한다.
- 대표 영상과 영상 용도는 별개이다. 자동 지정이 공식 영상/원곡/미르 가창을 의미하지 않으며 기존 용도를 임의로 설정하지 않는다.
- 6곡의 기능 샘플 중 5번에 복수 카테고리와 SOOP→YouTube→다른 시점의 YouTube를 배치해 확인할 수 있게 했다. 샘플 변경은 실제 곡에 대한 판단이 아니다.

## 구조와 데이터 격리
songbook-check.html / vite.songbook-check.config.js의 별도 진입점으로 운영 App/AuthProvider/songbookStore를 로드하지 않는다. 공통 URL 검증, 곡 검색·정렬, 가창 링크 병합·삭제 제외, 10초 안내 훅을 재사용한다. 공개 읽기 권한으로 빌드 시 목록 사본을 생성한다. 실제 신청 상태·카테고리·난이도·숙련도를 임의 변경하지 않으며 작성자·출처·개인 검토 내역은 가져오지 않는다.

편집/즐겨찾기는 기존 mir-songbook-check-v1:sample 또는 :snapshot 저장소만 사용한다. 관리자 체험은 검토 화면 전환으로 실제 관리자 인증이 아니다. 운영 DB/계정 권한·API 키·노래 추가/삭제·자동 수집/스케줄 변경은 없다. 사본은 시점을 표시하며 실시간 목록이 아니다. 공유 링크는 검토 릴리스에 한정되고 필터/관리자 모드/로컬 변경은 공유되지 않는다. 직접 신청 접수나 채팅 전송을 제공하지 않는다.

## 배포
songbook-check-preview.yml의 기존 Node24/검증/브라우저/공개 읽기 설정/SFTP stage-only 흐름을 유지한다. 추적된 소스만 git archive로 보관해 같은 커밋을 재현할 수 있게 했다. 빌드 결과·비밀 값·node_modules는 이 소스 아티팩트에 추가하지 않는다.

기존 yeop_deploy_ci.Remote의 호스트키 확인/새 파일 전송/SFTP read-back을 재사용하고 /web/_mir_site/_yeop_releases/새 릴리스 아래만 작성한다. 운영 라우팅 .htaccess 둘의 지문을 배포 전후 대조하며 운영 활성화는 하지 않는다. PHP/API/비밀 설정 파일은 배포하지 않는다. check-version.json의 reviewVersion은 2로 표시한다.

## 검증
npm run verify / npm run check:backend / 검토용 fixture build를 수행한다. 신규 8개 단위 검사로 자동 대표의 유효 URL·타임스탬프·순서·추가/제거·과거 브라우저 초안·카테고리 보존·작업 목록 일치와 화면 연결을 확인한다. 기존 대표 수동 선택 검사는 새 자동 규칙에 맞게 갱신하되 URL/권한/저장 실패 검사를 완화하지 않는다.

기존 9개 브라우저 그룹에 목록/상세 카테고리·첫 YouTube 자동 지정, 과거 초안 호환과 미지정 목록, 영상 삭제/추가/새로고침, 공개 사본 원본 비교의 4개 그룹을 추가한다. 320/390/768/1440/1920px에서 카테고리 모두 표시·가로 넘침을 확인한다. CI 로컬 및 실제 검토 주소에서 동일한 검사를 실행한다. 서버 변경 요청과 운영 인증/DB 호출을 차단한 상태로 브라우저 저장만 검사하며 실제 운영 곡은 시험 편집하지 않는다. 최종 실행 결과·SHA·검토 URL은 PR #99에 기록한다.

## 이후 통합 범위
운영의 노래 추가/외부 음악 검색/자동 수집 확인/삭제·복원은 검토 화면에 중복 구현하지 않았다. 실제 도입 시 새 대표 정책·공개 안내 저장과 기존 관리자 권한 통합은 검토 승인 후 진행한다.
