# 노래책 v4 운영 반영

## 요청과 범위
사용자가 승인한 4차 노래책을 feature/songbook → develop → main으로 merge commit 병합하고 기존 운영 배포 파이프라인으로 활성화한다. 기존 사이트와 동일한 아이디·비밀번호 로그인을 사용한다. 계정 권한을 임의로 부여하거나 미르님 숙련도를 자동 생성하지 않는다.

## 로그인
- 계정 페이지와 노래책 편집 로그인 모두 `usernameLogin.js`의 기존 `member-auth` login action을 사용한다.
- 로그인 입력은 아이디(text, autocomplete=username)와 비밀번호다. 아이디는 기존 가입 규칙의 4~24자 영문 소문자·숫자·점·밑줄·하이픈이며 앞뒤 공백과 대문자를 정규화한다. 비밀번호는 변경하지 않는다.
- 가입 인증/비밀번호 복구의 이메일 필드는 유지한다. 로그인 입력과 별개다.
- 서버에서 발급한 access/refresh token으로만 세션을 만든다. 운영 노래책은 사이트 공통 Supabase 클라이언트를 사용해 양방향 로그인/로그아웃 상태를 공유한다.
- 검토용 로그인은 별도 sessionStorage와 검토 전용 네트워크 허용 목록을 유지한다.

## 운영/검토 분리
새 `songbook_entries`, `songbook_ratings`, `songbook_editors`와 RLS를 배포했다. 기존 `songbook_preview_*`는 그대로 두며 복사하지 않는다. 이전 검토 화면에서 편집해도 운영 노래책에는 반영되지 않는다. 기본 342곡은 정적 카탈로그로 시작하고 운영 테이블은 편집/신규 곡/평점만 보관한다. 역할은 owner 한 명의 숙련도 편집, manager/admin의 곡 정보 편집으로 분리한다. 실제 owner 지정은 미완료이며 기존 관리자가 검증한 계정 UUID를 지정해야 한다.

운영에서는 검토 배지·변경점 링크·demo 편집을 숨기며 `/songbook/review`는 노래책으로 이동한다. 기존 검토 주소의 기능은 유지한다.

## 검증
기본 Node 테스트에 ID 로그인/세션 실패/입력 검증/검토 쓰기 제한/운영 테이블 분리 7건을 추가했다. 기존 포함 118건이 통과했다. 음악 검색/한국어 제목 PHP 테스트와 Python/PHP 문법도 확인한다.

`songbook-production-browser-check.py`는 운영 빌드를 릴리스 하위 경로에 띄우고 인증/DB 요청을 완전히 격리한 fixture로 검사한다. 아이디 로그인 실패·성공, 사이트와 노래책의 공유 세션, 새로고침, owner 평점 저장 요청, 양방향 로그아웃, demo 우회 차단, 반응형 화면을 검사한다. 실제 사용자 자격 증명을 사용한 로그인 성공 검증은 아니다.

실제 DB에서는 트랜잭션 안의 임시 계정/곡으로 owner 쓰기·revision 증가, manager 정보 수정과 평점 거절, 일반/익명 쓰기 거절, 운영/검토 분리를 검증하고 전체 rollback했다. 기존 콘텐츠·일배치를 수정하지 않았다.

배포 뒤 `songbook-live-check.py`는 운영 페이지/API를 읽기 전용으로 검증한다. 최종 실행 링크·병합/배포 커밋은 PR에 기록한다. 별도 팬아트 외부 원문 HTTP401 검사는 노래책 회귀 검사와 구분한다.
