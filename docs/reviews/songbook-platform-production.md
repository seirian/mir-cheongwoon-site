# 작업: 승인한 플랫폼 검색 운영 반영

## 목적과 완료 조건
검토한 Apple Music·YouTube 검색을 기존 운영 노래 추가·편집 화면에서 사용한다. 멜론은 삭제하지 않고 MELON_PAUSED 주석으로 유지한다. 기존 사이트 관리자만 저장하며 YouTube 결과는 가수 공란으로 서버에 저장·재조회·편집할 수 있다. 로컬 검토 페이지를 운영 페이지로 바꾸거나 검토곡을 자동 이관하지 않는다.

## 영향 범위와 계획
- 기존 SongbookV2Page/공통 SongEditor와 실제 songbookStore를 연결한다. 검토 옵션은 계속 별도이며 운영에는 검토 전용 안내/저장소를 쓰지 않는다.
- songbook_entries의 artist 길이 조건만 0~200자로 조정한다. NOT NULL, 관리자 RLS, 제목 필수, 중복 인덱스, URL 제한과 revision 검증은 유지한다. 자동 신규곡은 기존 가수 확인 규칙을 유지하고, 가수 없는 기존 수동곡에 연결하는 경로는 기존 ID를 사용한다.
- 운영 배포의 API 파일 목록에 플랫폼 검색/서버 전용 YouTube 유틸리티를 포함한다.
- 업로드·검증 이후, 활성화 전에 등록된 GitHub Secret으로 릴리스별 비공개 키를 설치하고 실제 YouTube 검색을 확인한다. 실패하면 운영 라우팅을 변경하지 않는다. 키는 빌드 환경/공개 응답/아티팩트에 넣지 않는다.
- feature → develop 검증/병합 후 develop → main 보호 규칙을 통과해 merge commit 병합, 기존 Actions 배포 및 실제 운영 읽기 검증, develop fast-forward 동기화.

## 검증
기존 Node/빌드/백엔드/권한/리뷰/영상순서 검사를 유지한다. 운영 옵션 단위 검사, 비밀 설정 실행 문맥 검사, 격리 Postgres 가수 공란·수정·중복·일반회원/익명 차단, 실제 운영모드 앱에서 모의 인증/DB로 플랫폼 검색·공란 서버 저장·재조회·수정/실패/중복 검사를 추가한다. 실제 배포에서는 로그인/운영 곡 쓰기 없이 새 API의 Apple 및 YouTube 검색과 비밀 경로 차단을 확인한다. 최종 실행 URL과 SHA는 PR에 기록한다.

## 보존 범위
기존 운영 노래/숙련도/가창 승인·제외 결정을 직접 수정하지 않는다. 관리자 계정, RLS, 자동수집 Edge Function 및 일배치/Discord 스케줄은 변경하지 않는다. 검토 브라우저에 저장한 초안도 삭제하지 않는다. YouTube 채널명을 가수로 추정하거나 영상 선택만으로 미르님 가창/신청 가능 여부를 확정하지 않는다. API 키 Google Cloud 제한 설정은 기존 그대로이며, API 성공을 모든 제한 설정 검증으로 설명하지 않는다.
