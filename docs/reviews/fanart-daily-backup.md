# 실시간 우선 + 01:00 KST 팬아트 일배치 백업

## 요청/완료 기준
일정표 접속 시 기존 실시간 API(정상 캐시 30분)를 우선한다. 실패 때 매일 01:00 KST에 독립 수집한 최신 성공 게시글/이미지 저장본을 사용한다. 여러 본문 이미지는 저장본에서도 슬라이드로 보여준다. 배치 실패는 이전 성공본을 보존한다. 홈/일정 편집/회원 데이터는 변경하지 않는다.

## 경로
- 기존 `naver-fanart.php`: 기존 수집/TTL 유지. 실패 시 공유 일배치 저장본, 없을 때만 기존 긴급 백업 순서.
- `naver-fanart-backup.php`: 원본을 호출하지 않는 읽기 전용 백업 API. 주 API HTTP/JSON/네트워크/25초 타임아웃 또는 이미지 전체 실패 시 클라이언트에서도 사용. 백업마저 실패하면 기존 출처/오류 안내 유지.
- `naver-fanart-daily.php`: 정상 캐시를 재사용하지 않고 원본 수집+실제 이미지 다운로드(최대12장)를 수행한다. 모든 이미지가 검증된 경우에만 저장본 전체를 원자 교체. 한 장 실패/접근 제한/45초 전체 예산 소진이면 이전 성공본 유지. 상태와 최근31회 실행 결과 별도 기록.
- 데이터는 릴리스 밖 `_fanart_daily`에 보존. `.htaccess`로 직접 접근 금지. 배포는 보호 설정만 확인하고 저장본/실행 기록은 덮어쓰지 않는다. 두 고정 슬롯(각 최대24MiB)과 해시 이미지 API; URL/파일 경로 입력 불허, 해시/MIME/크기 검증. 직전 성공 이미지도 다음 저장 시도 전까지 읽을 수 있다. 내용이 같은 이미지도 해시로 중복 제거한다.
- stable `/api/naver-fanart-daily.php`는 항상 현재 활성 릴리스로 연결. 과거/프리뷰 릴리스는 배치 실행 거절. 공개 고정 원본 캐시 워밍 엔드포인트로, 외부 입력으로 데이터/일자/원본/재시도를 지정할 수 없고 서버 한국 날짜별 단1회/01:00 이후만 동작한다. 마우스/페이지 방문은 이 배치 엔드포인트를 호출하지 않는다.
- 스케줄은 기존 Supabase pg_cron에 **0 16 * * *** (UTC), 즉 매일01:00 KST로 등록. GitHub Actions 지연/PC 가동 상태에 의존하지 않는다. `supabase/ops/fanart_daily_cron.sql`은 배포 후 적용하는 명시적 운영 설정이다.

## 검증/운영
PHP 오프라인 원자 저장/실패/동시성/이중 슬롯/실제 API 테스트, JS API우선/실패 전환 검사, PC/모바일 브라우저 회귀와 기존 팬아트 검사 수행. 수집 날짜와 게시 날짜는 분리 표시. 최초 연결은 정해진 시각을 기다리지 않고 같은 배치 경로를 한 번 실행해 저장본을 확보하되 실제 수행 시각을 기록한다.
cron의 succeeded는 HTTP 디스패치 성공일 뿐이다. 최초 실행에서 pg_net의 최종 HTTP 응답/실제 저장 이미지/슬라이드까지 확인하고 PR에 결과를 남긴다. 미래 01:00 예약 실행을 이미 확인한 것으로 보고하지 않는다. 원본에 새 글이 없으면 게시 날짜는 이전 날짜일 수 있다. 소스 자체가 제한되면 배치도 실패하며 마지막 정상 저장본의 실제 수집 시각을 표시한다. 기존 Discord 일정 점검 함수/다른 배치 설정은 변경하지 않는다.
