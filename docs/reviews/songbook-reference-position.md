# 수집된 참고 위치와 곡별 시작점 구분

## 요청과 변경
곡별 시간이 있는 항목과 관리자가 확인한 항목은 기존처럼 시:분:초로 자동 입력한다. 여러 곡에 공통으로 붙은 구간 시작점만 있는 경우에는 빈칸의 이유를 설명하고 별도 ‘수집된 참고 위치’와 새 탭 VOD 링크를 표시한다. 참고 위치를 해당 곡의 실제 시작점으로 자동 확정하지 않는다.

참고 위치는 수정 중인 입력값과 별개로 유지한다. 실제 위치를 입력하면 기존 ‘입력한 위치에서 VOD 확인’ 링크로 재확인할 수 있다. 승인된 항목을 다시 열 때는 관리자가 확인한 위치가 우선한다. 0초를 미확인으로 오해하지 않고, 누락/범위 밖의 값으로 잘못된 링크를 만들지 않는다. 형식 검증·빈칸 승인 차단·정수 초 API는 그대로다.

## 보존
입력값은 항목을 여는 시점에만 초기화한다. 검색/곡 선택·VOD 복귀·같은 계정의 권한 재검증 시 사용자 수정값과 패널을 유지한다. 제외는 시간 입력 없이도 가능하며 완료 안내를 유지한다. DB/Edge/RLS/스케줄러/자동 수집 분류/실제 곡·숙련도·검토 결정은 변경하지 않는다.

## 검증
새 순수 상태 검사와 기존 전체 Node/빌드/문법/SQL 검사, 기존 30개 애플리케이션·리뷰 브라우저 그룹을 유지한다. 실제 TimelinePanel 오프라인 fixture에서 자동 입력·빈칸+참고 위치·참고 VOD 새 탭·복귀와 권한 재검증·수정값과 두 링크 분리·승인 후 재열기·항목 전환을 추가 검사한다. 데스크톱/모바일 화면을 확인하며 운영 검사는 읽기 전용으로 한다.

전체 로컬 clone은 컨테이너 DNS 제한으로 실패했으므로 연결된 GitHub 최신 develop 기준으로 수정하고 기존 Node24 CI에서 전체 검증을 실행한다. 완료한 CI·브랜치·배포·운영 확인 결과는 PR에 기록한다.
