# 자동 수집 확인 목록 검색

## 목적
운영 노래책의 관리자 자동 수집 확인에서 곡을 찾아 검토할 수 있도록 한다. 검색은 현재 탭 전체에 적용한 뒤 8건 단위로 나누며, 현재 페이지 8건만 필터링하지 않는다.

## 범위와 동작
- 곡명·가수·타임라인 원문·VOD 번호 부분 검색. 영문 대소문자와 공백/Unicode 표기를 정리한다. 여러 단어는 모두 포함되는 항목을 찾고 %, _, *, 괄호·따옴표는 검색 문자열일 뿐 쿼리 문법이 아니다.
- 검색 또는 Enter로 적용하고 결과 수·검색어·빈 결과 안내 및 검색 초기화를 제공한다. 모든 상태 탭에 동일한 검색어가 유지된다. 공개 노래책 검색과 ‘기존 곡 찾기’는 별개다.
- VOD 새 탭 확인, 권한 재확인, 새로고침, 승인/제외 후에도 검색어와 펼침 상태를 유지한다. 입력 중인 검토 폼은 백그라운드 갱신으로 덮어쓰지 않는다. 검색/탭/페이지를 명시적으로 바꿀 때만 선택을 해제한다.
- 검색어는 기존 계정별 sessionStorage 보기에만 보관하며 공개 URL·운영 노래에는 저장하지 않는다.

## 서버·보존
검색용 SECURITY INVOKER STABLE 함수 하나를 추가하며 기존 admins 확인 + RLS를 유지한다. 일반 회원과 익명 사용자는 검색할 수 없다. GET RPC로 조회하며 동적 SQL이나 외부 음악 API를 호출하지 않는다. 검색어 200자, 페이지 크기 50건 이내. 기존 목록 조회는 그대로 유지한다. 기존 노래/난이도/숙련도/승인·제외 결정/수집 스케줄/키 설정에는 변경이 없다.

## 검증·배포
Node 정규화/요청/오류/상태 회귀, 격리 PostgreSQL 전체 검색·페이지 수·특수문자·RLS 검사, 실제 컴포넌트 브라우저에서 검색/페이지/제외/타임스탬프/권한/모바일 검증을 수행한다. 기존 전체 테스트를 통과한 뒤 additive SQL을 적용하고 develop→main PR과 기존 GitHub Actions로 운영 배포한다. 실제 운영 점검은 조회만 한다. 최종 SHA·Actions·보고서는 PR에 기록한다.
