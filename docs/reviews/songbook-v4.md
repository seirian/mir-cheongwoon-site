# 노래책 4차 검토: 한국어 제목 우선

## 목적 및 완료 조건
사용자가 `영물이다`를 검색하면 선택 전에 `영물이다 — 이오몽`으로 이해할 수 있게 한다. 검색어를 번역하거나 그대로 곡명에 대입하지 않는다. 외부 음악 검색 범위, 다중 VOD, 이미지, 난이도, 소유자 전용 숙련도와 검토 환경 분리는 유지한다.

완료 조건: 한국어 대표 제목과 해외명 별칭 자동 저장, 한·영 검색 유지, 기존 편집 제목 보호, 반주/라이브 별도 표시, 실제 공개 API 및 브라우저 검증, feature/songbook만 변경하고 운영 활성화 없음.

## 선택한 방법
추가 유료 API나 국내 사이트의 상시 HTML 수집에 의존하지 않고 기존 iTunes/MusicBrainz 조회에 표시명 결정 단계를 추가한다.

우선순위는 ① 이미 저장된 운영자 제목 ② 곡 ID에 연결된 검토 완료 국내명 ③ 같은 ID의 한국 스토어 한국어 제목 ④ 다른 지역 한국어 제목/명시적인 한국어 이름 별칭 ⑤ 원문 유지다. MusicBrainz의 오탈자 검색 힌트나 서로 충돌하는 별칭을 대표 제목으로 쓰지 않는다. 별칭은 응답에 존재하는 경우에만 활용한다. 모든 곡의 한국어명 확보를 보장하지 않는다.

`server/api/_songbook_korean_titles.php`는 확인한 이름 연결의 초기 레지스트리다. 현재 **영물이다 일반 음원과 inst 두 트랙만** 별도 등록했다. 특정 검색어에 가짜 응답을 반환하는 코드는 없지만, 이 두 트랙의 표시명은 검증된 정적 연결 정보에 기반한다. 다른 곡의 국내명 교정을 자동으로 모두 수집하는 기능은 아니다.

동일 ID 외에도 가수, 기존 곡명, 앨범 ID, 트랙 버전을 대조한 뒤 교정한다. 검토된 별칭 검색은 실제 음악 API의 ID 조회로 이어진다. 실제 API가 실패하면 레지스트리만으로 검색 성공을 가장하지 않는다. 기존 API의 요청·크기·속도 제한을 유지하고, 이전 배포와 API 호출 제한 파일을 공유한다. 응답 캐시는 버전과 레지스트리 해시로 구분한다.

동일한 제목·가수만으로 서로 다른 녹음 ID를 합치지 않는다. 저장 시에는 기존 음악 서비스 ID를 사용해 같은 곡의 재등록을 막는다. 이름만 일치하는 후보가 여러 개면 자동 편집 대상을 정하지 않는다.

## UI 및 저장
검색 결과의 주 제목을 한국어로 표시하고 해외명은 접을 수 있는 `다른 표기`와 저장 별칭으로 남긴다. 반주는 `반주`, 실황은 `라이브`로 구분하고 제공된 발매일/재생 시간도 표시한다. 한국 가수의 미확인 해외명은 `원문 제목 · 한국어명 미확인`이라고 표시한다.

운영자가 저장한 제목은 검색/가져오기에서 유지한다. 한국어 제목 제안은 별도 버튼으로만 적용하며, 기존 제목은 별칭으로 보존한다. 새 곡은 한국어 제목과 원래 이름 별칭이 함께 채워진다. 외부 정보 가져오기가 기존 카테고리/VOD/난이도/숙련도를 덮어쓰지 않는다.

기존 테이블 필드를 사용하며 **4차 작업에서 DB 스키마나 저장된 운영 데이터를 변경하지 않는다**. 미르님 계정 권한도 자동 지정하지 않는다. 체험은 localStorage에만 저장한다.

## 검증
- `npm run verify` (현재 기존 포함 Node 111개 테스트)
- `npm run check:backend`
- `php tests/songbook-search-test.php`
- `php tests/songbook-localization-test.php`
- `python scripts/songbook-v4-browser-check.py --url <preview-root>/ --out <reports> --live-catalog`

브라우저 검사는 2·3차 회귀 검사도 호출한다. 실제 서버 검색과 DOM의 첫 결과가 `영물이다`인지 확인한다. 모의 검색과 실제 검색은 별도 단계로 구분한다. 로컬 컨테이너의 브라우저 접속 제한으로 해당 환경의 화면 검증은 완료 처리하지 않으며, GitHub Actions의 로컬 서버 및 공개 배포 주소에서 실행한다. 이 검증은 모든 영상 재생/전체 국내명/실사용 계정 로그인을 전수 검증한다는 뜻이 아니다.

배포는 기존 stage-only 스크립트를 사용하고 운영 라우팅의 전후 해시, noindex, HTTP 200을 확인한다. PR 본문에 최종 커밋/실제 URL/검증 보고서를 기록한다. 과거 버전의 공개 Git 이력과 배포본은 삭제하지 않는다.
