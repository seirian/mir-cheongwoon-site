# SOOP 다시보기 타임라인 자동 반영

## 범위
alice427의 공개 REVIEW 다시보기 중 2025-01-01 KST 이후 게시된 자료만 대상으로 한다. 페이지 번호가 아니라 게시 시각(reg_date)을 사용하고, REVIEW 목록에 섞이는 일반 업로드는 제외한다. 7일은 방송 시작이 아니라 게시 이후 168시간이다.

## 수집과 판정
최상위 댓글과 이어지는 답글을 전부 읽고 페이지/개수/방송국/VOD 식별자를 검증한다. 가창 표시와 노래 구간, 곡명·원곡자·다국어 별칭을 대조한다. 다른 출연자의 노래나 감상/방종곡/반주 재생은 자동 반영하지 않는다. 부분 가창, 연습, 합창, 동명곡, 원곡자 불명, 곡별 시간이 없는 목록과 새 작성자의 기록은 관리자 확인 대상으로 남긴다. 최초 검토한 작성자 식별자는 해시만 비공개 설정에 보관한다. 댓글 원문 전체, 닉네임, IP, 프로필은 서비스 데이터에 저장하지 않는다.

명확한 항목은 기존 곡의 영상으로 연결하고 없는 곡은 별도 자동 곡 목록에 추가한다. 자동 신규 곡은 신청 확인 전, 난이도/숙련도 미설정이다. 과거 가창이 현재 완창 가능 또는 신청 승인이라는 뜻은 아니다. 오디오 인식이나 VOD 전체 청취 검증은 수행하지 않는다. 자동 반영 항목도 관리자가 제외할 수 있다.

## 수동 정보 보호와 관리자 확인
수동 songbook_entries와 songbook_ratings는 자동 작업이 수정하지 않는다. 수동 제목/분류/난이도/신청 상태와 숙련도가 우선한다. 자동 영상은 별도로 저장하며 목록에는 최근5개, 상세에서는 페이지별 전체 이력을 제공한다. 수동 편집 입력에 자동 영상을 섞지 않는다.

관리자에게만 페이지 하단 ‘자동 수집 확인’이 보인다. 정확한 기존 곡을 선택하거나 새 제목·가수를 입력하고 가창 시작 시간을 확인해 승인한다. 구간 목록은 개별 시간 입력이 필수다. 승인/제외는 revision 충돌을 검사하고 다음 수집이 뒤집지 않는다. 완전한 댓글 조회에서 사라진 근거만 비활성화하며 수동 곡은 삭제하지 않는다. 비공개로 바뀐 VOD는 다음 목록 갱신에서 자동 링크를 제거한다. 삭제되어 목록 자체에서 사라진 VOD나 원본 재생 불가는 완전 검증 대상이 아니다.

## 스케줄과 장애 처리
Supabase pg_cron 매시35분, 한 번 최대12개, 요청 간650ms, 90초 처리 예산. 목록은 하루 한 번 날짜 경계까지 갱신한다. 게시+7일 이후 첫 검사, 게시28일 이내 매일, 90일 이내 매주, 이후 매30일 재검사한다. 실패는 다음날 다시 시도하고, 빈 댓글과 응답 오류를 구분한다. 전역 임대 잠금으로 최초 일괄 작업과 정기 실행을 분리한다. 실패/불완전한 응답으로 기존 노래를 지우지 않는다.

기존 배치 Discord 채널로 신규 곡/실패와 일일 요약을 알린다. 수집 자체가 시작되지 않는 플랫폼 장애는 pg_cron/Edge 로그에서 점검한다. 기존 일정/쇼츠/팬아트 배치 스케줄은 변경하지 않는다.

## 인증과 배포
정기 호출은 비공개 설정의 전용 토큰만 허용한다. 사용자 JWT는 기존 admins 확인 후 후보 승인/제외만 가능하다. 최초 일괄 작업은 GitHub OIDC의 서명, audience, repository/owner 불변 ID, ref와 정확한 workflow_ref를 검증한다. 서비스 키를 GitHub나 브라우저로 전달하지 않는다. 수집 RPC는 SECURITY INVOKER이며 service_role에만 EXECUTE를 허용한다. 공개 view는 security_invoker=true이다.

조사 artifact는7일 후 만료되며 저장소/배포 번들에 넣지 않는다. backfill은 현재 메타데이터와 일치하는 조사 결과를 재사용하고 만료 시 공개 댓글을 다시 읽는다. 기본곡은 검증한 GitHub 작업이 src/data/songbookCatalog.json의 곡 정보만 비공개 설정에 동기화한다. 수동·자동곡은 DB 최신 값을 읽는다.
