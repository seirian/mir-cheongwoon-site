# 이용자 안내 1차 검토안 · 2026-10-08

## 요청과 범위
회원가입을 받는 mir.yeop.net의 개인정보 처리 구조 및 고지 필요성을 확인하고, 공통 푸터에서 열리는 개인정보처리방침·이용약관·운영정책 초안을 별도 검토 릴리스에 만든다. 운영 활성화, 실제 회원가입 변경, 계정 삭제, DB 쓰기·스키마 변경은 하지 않는다.

개발 기준: develop f1602e789867687f88862588929b9abb8b8524e1. 작업 브랜치: feature/privacy-policy-review. main/develop를 수정하지 않는 1차 검토용 브랜치다.

## 확인한 사실
- AccountPage: 아이디·이메일·비밀번호·비밀번호 확인을 입력받아 Supabase Auth 가입. 이메일 인증·복구 경로 존재. 회원가입 부분에 약관·개인정보 안내 없음.
- member_profiles: user_id, username, email, created_at. 운영 RLS 활성화 및 자기 프로필 조회 정책 확인.
- Auth 스키마: 계정·인증·세션 정보. 최소 집계에서 sessions.ip 및 user_agent 실제 저장 확인; audit_log_entries.ip_address 비어 있음. IP 필드 존재만으로 실제 저장을 단정하지 않았음.
- 운영 Supabase DB 리전 ap-south-1(인도). DB 리전은 모든 처리·지원·메일 국가의 증거가 아님.
- 확인한 계정 UI: 비밀번호 변경·로그아웃. 직접 탈퇴 UI 및 대체 접수·삭제 절차 미확인. 함수명 검색만으로 모든 삭제 방법이 없다고 단정하지 않음.
- 회원별 이메일·아이디·IP 원문, 비밀번호 해시, 토큰을 조회하지 않음. DB 변경 없음.
- 소스에서 Google Fonts와 YouTube 썸네일·privacy-enhanced embed, 노래책 브라우저 저장 참조 확인. 범위별 실제 네트워크·보관기간 최종 확인 필요. 단순 패턴 검사에서 분석 도구 참조가 없다는 사실이 모든 추적·서버 로그 부재를 증명하지 않음.

## 개인정보 여부와 공개 의무를 구분
회원 식별에 사용되는 아이디와 이메일 및 연결 정보는 개인정보 보호법 제2조상 개인정보로 판단한다. 일반 개인정보처리자의 처리방침 공개는 제30조 및 시행령 제31조 대상이다.

단, 제58조제3항은 동창회·동호회 등 친목 도모를 위한 단체 운영에 제15조·제30조·제30조의3·제31조를 적용하지 않는다(2026-09-11 시행 조문 확인). 표준 개인정보 보호지침 제2조는 인터넷 커뮤니티를 단위로 한 공통 관심사 모임도 친목단체 정의에 포함한다. 따라서 모든 팬사이트를 무조건 의무/예외라고 단정할 수 없다. 실제 단체 구성·운영 목적·활동 및 해당 처리와의 관련성을 확인해야 한다. 공개 사이트와 회원 기능만으로 예외 여부를 확정하지 않았다. 이번 초안은 예외를 가정해 고지를 생략하지 않는 안이며 개인정보 자체가 없어지는 것이 아님을 명시한다.

방침 공개와 수집 동의, 약관 계약 동의는 다르다. 법 적용 범위 및 필수 처리의 제15조제1항제4호 적용, 제28조의8 국외 이전 근거를 실제 목적·필요성·고지 요건과 함께 결정해야 한다. 별도 동의가 항상 유일한 방법이라고 보지 않는다.

## 정식 반영 전 미확정 사항
친목단체 예외의 적용 여부 / 실제 책임자·연락처 / 회원·로그·메일·백업의 보유기간 및 파기 / 탈퇴·권리행사 / 수탁 법인·메일·호스팅·재위탁·해외 처리 세부 / 아동 회원 정책 / 외부 콘텐츠·분석 및 서버 로그 최종 점검. 임의의 연락처·기간·시행일을 생성하지 않는다. v0.1 미시행으로 모든 문서에 표시한다.

## 구현
- /policies/review, /policies/privacy, /policies/terms, /policies/operation
- 공통 푸터 링크, 문서 목차, 모바일 표 내부 스크롤, 직접 URL/새로고침용 HTML 메타데이터
- 가입 안내 시안: 실제 입력란·제출·개인정보 저장 없음. 개인정보처리방침에 대한 포괄 동의 체크박스 없음.
- VITE_REVIEW_PREVIEW=true와 VITE_POLICY_PREVIEW=true를 모두 요구. 기존 read-only fetch, 인증 세션 비저장 동작 사용.
- 정책 검토 홈은 별도 읽기 전용 이미지 컴포넌트 사용. 기존 이미지 관리자 로그인·업로드·목록 POST를 마운트하지 않음. 운영 홈 이미지를 변경하지 않고 공개 URL로 조회.
- 모든 검토 메타데이터 noindex. noindex는 접근통제가 아니므로 비밀·회원값 포함 금지.
- stage-policy-preview.py: ACTIVATE=false 고정, 기존 두 라우팅 파일 fingerprint 비교, staged만 허용. 기존 배포 스크립트 변경 없음.

## 검증 이력과 재검증
- 첫 실행: Node 24 verify 298개 통과, 백엔드 Python55/PHP16 문법 통과. 로컬 Vite preview의 release base 불일치로 화면 검사 실패. 업로드하지 않음.
- 두 번째 실행: 경로 수정 후 데스크톱/모바일 16개 화면 검사 통과, JS 예외0. 홈 이미지 목록 조회 POST 2건이 테스트 차단기에 잡혀 마지막 무요청 조건 실패. 이는 storage.list의 읽기 요청으로 소스 확인. 실제 전송은 차단되었고 계정 쓰기 아님. 업로드하지 않음.
- 수정: 정책 검토에서 홈 이미지 관리자 자체 분리, 어두운 실제 푸터 배경의 명도 대비 개선, 친목단체 예외 표시, 잘못된 문서 경로 방어. 새 전체 검증 결과는 이후 Actions 로그와 artifacts 기준으로 확인. 이 문서는 아직 새 실행의 통과를 선언하지 않음.
