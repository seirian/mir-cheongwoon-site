# 팬아트 9/21 저장본 고정 문제

## 사용자 신고와 원인
운영 팬아트 API가 articleId=163918, sourceDate=2026-09-21, fallback=true, stale=true를 반환했다. 직전 슬라이드 작업은 이미지 표시 기능만 완료했으며 원본 수집은 실패한 상태였다.
익명 진단에서 게시판 목록은 HTTP 200으로 최신 게시글 165311(2026-09-30 00:21 KST)을 제공했으나 기존 apis.naver.com/cafe-web/cafe-articleapi/v3 본문 경로는 HTTP 500/errorCode 9999를 반환했다. menuId/boardType 추가만으로 해결되지 않았다.
실제 공개 카페 페이지의 iframe 네트워크에서 본문 요청이 https://article.cafe.naver.com/gw/v4/cafes/31003156/articles/165311?query=&useCafeId=true&requestFrom=A 로 HTTP 200을 반환하는 것을 확인했다. 로그인/쿠키/우회 수단을 사용하지 않았다.

## 수정 범위
- 수집기의 본문 주소를 확인된 v4 게이트웨이로 변경한다. 허용 목록 확장은 해당 카페의 숫자 게시글 read 경로 하나로 제한한다. DNS 고정, 사설 IP 금지, 크기/시간 제한과 401/403/429 즉시 중단은 유지한다.
- 본문 읽기 제한/블라인드 및 ID 불일치를 거절한다. 기존 날짜별 게시글 선정, 작성자·원본 링크, 같은 게시글 이미지 최대 12장 슬라이드는 유지한다.
- 수집 실패 시 백업을 RECENT로 부르지 않고 ‘저장본 · 게시 날짜’로 표시한다. 카드의 실패 안내에도 저장본 게시 날짜를 명시하고 API에 최근 확인 시각(checked_at)을 따로 제공한다.
- 다음 배포가 최근 성공 캐시 대신 과거에 복사해 둔 fallback 파일을 먼저 재사용하던 순서를 수정한다. 현재 릴리스에서 검증된 성공 캐시와 일치하는 이미지가 있으면 그것을 우선 보존한다. 잘못된 해시·외부 링크는 여전히 거절한다.
- 진단용 임시 워크플로는 최종 코드에서 제거한다. 계정, 비밀번호, 일정 편집, 홈 PC/모바일 디자인, DB/RLS, Storage는 변경하지 않는다.

## 검증 계획과 기준
- PHP 회귀 검사: 새 게이트웨이 계약, 호스트/경로 제한, 읽기 거절 중단, 이미지 추출 및 실제 fallback 엔드포인트.
- Python 오프라인 5개: 최근 성공 캐시 우선, 구형 백업 호환, 이미지 해시 불일치·수집 실패·손상 파일 거절.
- 실제 React/PHP 브라우저 검사: 기존 슬라이드와 9/21 저장본 표시를 1440/390px에서 검증한다.
- 별도 source-contract 작업은 현재 수집기로 목록 한 번/본문 한 번만 익명 조회한다. 실제 원본 수집 성공과 단순 백업 표시 성공을 구분한다.
- 운영 live 검사에 --require-fresh를 추가한다. fallback/stale 응답 또는 오래된 조회 시각이면 검사 실패로 남기며 정상 갱신으로 보고하지 않는다. 실제 운영 게시 날짜·제목·이미지 수를 결과에 기록한다.

네이버의 비공식 웹 내부 API는 향후 변경될 수 있다. 현재 동작 검증 결과를 향후 무장애 보장으로 해석하지 않는다. 실제 운영 전환 완료 여부와 관측한 날짜는 PR 완료 기록에 남긴다.
