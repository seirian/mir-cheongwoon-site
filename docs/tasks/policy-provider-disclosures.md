# 개인정보처리방침 5·6절의 진행상태 문구 정리

## 요청과 범위
사용자가 표시한 네 곳의 ‘확인 중’을 삭제하거나 사실에 근거한 문구로 바꾼다. 기존 운영 기준은 재승인을 요청하지 않는다. main/develop 043d04ce4b9d27e7dd7c1febfc7da5cd70f4c0ba에서 시작하고 AGENTS.md, architecture.md, harness.md를 확인했다. 로컬 clone은 DNS 실패로 진행되지 않아 GitHub 연결의 정확한 base tree에 필요한 파일만 변경하고 기존 Actions에서 전체 검증한다. 원격 PC, 권한 확대, 보호 규칙 변경은 사용하지 않는다.

## 공개 문구
- 5절은 네 서비스와 각 처리 업무·정보를 모두 유지하면서 내부 점검용 ‘확인 범위’ 열을 제거한다. Supabase/NAVER/웹 호스팅/인증·복구 메일의 행을 삭제하지 않는다. NAVER 문의메일과 인증·복구 메일의 구분은 본문에 남긴다.
- 6절의 이전 국가는 ‘운영 DB 저장 국가: 인도(뭄바이, ap-south-1)’로 정확히 범위를 표시한다. 모든 지원·재위탁·메일 처리가 인도에서만 이루어진다고 단정하지 않는다.
- Supabase DPA 6.1과 공식 재수탁자 안내를 대조했다. DB 저장 국가 외 지역에서의 지원·재위탁 처리 가능성을 본문에 유지하고 6절에 공식 DPA/재수탁자 목록 링크를 제공한다. 사업자의 전체 재수탁자 목록이 이 프로젝트에서 모두 사용된다는 의미로 복사하지 않는다.
- 5·6절의 숨겨진 과거 note도 운영 데이터에서 제거하고, 이 문서와 Git 이력에 점검 범위를 보존한다. 보유·파기 절, 회원가입·탈퇴 구현, 책임자 옆군 표기, 약관·운영정책, 버전/최초 공개일은 변경하지 않는다.

## 사실과 법적 범위
호스팅 계약상 사업자명, 실제 SMTP 사업자/처리국가 및 외부 로그·백업 기간이 이번 문구 변경으로 새로 확인된 것은 아니다. ‘확인 중’을 ‘확인 완료’로 바꾸거나 임의의 국가·기간을 기재하지 않는다. 내부 진행상태 문구는 법정 고지항목 그 자체가 아니지만, 삭제 또는 공식 자료 링크만으로 모든 위탁·국외 이전 고지 요건이 충족됐다고 주장하지 않는다. 기존 기술·사업자 확인 과제는 유지되며 이번 요청은 표시·문안 정리다. 사용자에게 이미 확정한 운영 기준의 재승인을 요구하지 않는다.

공식 대조 자료:
- https://supabase.com/legal/customer-resources/data-processing-addendum (6.1 위치, 6.2 재위탁)
- https://supabase.com/legal/customer-resources/subprocessor-list
- 개인정보 보호법 제26조, 제28조의8의 위탁/이전 고지 구분

## 검증과 배포
기존 삭제 범위 회귀검사는 유지하고 5절의 ‘확인 중’ 존재를 요구하던 과거 검사를 이번 요구에 맞게 부재 검사로 변경한다. 네 서비스/업무 보존, 2열 표, 주된 DB 국가의 범위, 국외 지원·재위탁 가능성과 공식 링크, 미확인 사실의 확정 표현 방지를 새 테스트로 검사한다. PC·모바일 직접 접속·새로고침·푸터 이동 검사에 5·6절 문구/링크 검증을 추가하고 두 절의 스크린샷을 저장한다.

Node24 전체 verify, backend syntax, 정책 UI 및 기존 회귀검사가 통과한 뒤 develop → main PR을 merge commit으로 반영한다. 기존 GitHub Actions 배포/롤백 검증 결과와 공개 주소의 실제 결과를 확인하고 develop을 main과 fast-forward 동기화한다. 실행되지 않은 검증은 완료로 보고하지 않는다.
