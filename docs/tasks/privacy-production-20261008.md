# 개인정보·계정 정책 운영 반영 · 2026-10-08

## 승인된 범위
3차 검토안의 필수 계정정보 처리 근거·최소 수집 방식을 유지한다. 문의메일은 답변·처리 완료 후 불필요해지면 지체 없이 파기한다. 분쟁 진행 중인 기록만 실제 근거·필요 범위를 구분하고 종료 후 파기한다. 관리자 탈퇴는 공용 자료·권한 인계 후 처리한다. 공개 담당자는 옆군, 연락처는 sengyb@naver.com으로 유지하며 실명은 게시하지 않는다.

사용자는 develop → main 병합 및 기존 GitHub Actions 운영 배포를 승인했다. 원격 PC는 사용하지 않는다. AGENTS.md의 GitHub 권한 구분 지침을 보존한다. 작업 기준은 feature/privacy-production 9e2996c, main/develop f1602e78이다.

## 구현
- 검토 v0.1~v0.3 소스·기존 릴리스는 유지하고 별도 policyPublished.js 및 PublishedPolicyPage를 운영에 연결한다.
- 공통 푸터 3문서와 문의메일 링크, 가입 버튼 전 필수 정보 안내 및 별도 약관 확인란을 적용한다. 추가 나이 정보나 개인정보처리방침 포괄 동의는 받지 않는다.
- 신규 가입은 약관 버전·클라이언트 동의 시각을 기존 Auth user_metadata에 함께 전달한다. 이 값은 이용자 수정이 가능한 편의 기록이며 불변 감사증거·권한 근거가 아니다. 기존 회원의 동의는 자동 간주하지 않는다.
- /account의 기존 비밀번호 재확인 탈퇴 구현을 운영에 연결한다. 배포된 member-withdrawal v2 소스와 저장소를 대조했다. JWT gateway 검증과 서버 사용자·비밀번호 재확인, 관리자 보호, hard delete 및 삭제 확인을 유지한다.
- mir_policy_deploy_ci.py가 기존 mir_shared_root_deploy_ci.py의 원자적 배포·롤백 엔진을 재사용하며 정책 라우트와 공개 UI 검사를 추가한다. 공개 UI 실패는 기존 activation try/except 안에서 롤백된다. 새 스크립트가 운영 entry이며 기존 엔진은 변경하지 않는다.

## 검증과 남은 범위
Node24 Actions 전체 verify, backend syntax, Deno 검사, PC·모바일 공개 정책/가입 안내와 합성 계정 탈퇴 검사를 실행한다. 실행 결과는 Actions와 artifacts를 기준으로 확인한다. 운영 인증 endpoint의 무인증 401도 확인한다.

운영 DB에 테스트 회원을 직접 삽입하는 요청은 안전 검사에서 실행되지 않았다. 우회하거나 실회원의 비밀번호·계정으로 검증하지 않는다. 따라서 실제 운영 회원을 생성·삭제하는 E2E가 완료됐다고 보고하지 않는다. 합성 계정 브라우저/API 검증과 실제 데이터 삭제 증거를 구분한다.

## 미확정 법적·사업자 사실
운영자 요청에 따라 옆군 표시를 유지한다. 닉네임만으로 개인정보 보호책임자 성명 등 법정 기재 요건 충족을 보장하지 않으며, 가상 담당부서를 만들어 회피하지 않는다. 이 위험은 사용자에게 이미 설명했다.

호스팅의 계약상 사업자명·실제 SMTP·재위탁 국가·외부 로그/백업의 실제 보관기간은 도구에서 확인되지 않았다. 추정 업체명·기간을 법정 고지로 꾸미지 않고 공개 페이지에 확인 범위를 명시한다. 기술 배포 완료는 법적 완결성 인증이 아니다. 문의메일 실제 파기는 운영자의 메일함 관리 업무이며 이 배포가 메일을 자동 삭제하지 않는다.
