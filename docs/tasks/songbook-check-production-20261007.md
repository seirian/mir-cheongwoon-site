# 노래책 3차 검토안 운영 통합

## 승인 및 백업
사용자는 최종 검토안의 develop/main 반영을 승인했고, 변경 전에 main 기준 backup_20261007 생성을 요청했다. 다른 쓰기 작업 전에 GitHub에서 이 브랜치를 만들고 bc1cea3e01aaa4d3272e46050f8bb0772e0b0356과 일치하는 것을 확인했다. 백업 브랜치는 이후 이동/수정하지 않는다. 이것은 코드/설정 백업이며 실시간 DB나 외부 영상의 백업이 아니다.

## 완료 조건
- 3차 화면(카테고리 우측의 YouTube/SOOP, 화살표 없음), 상태 검색/복사/빠른 수정 운영 통합.
- 브라우저 전용 샘플/체험/저장은 운영 경로에 제공하지 않는다. 기존 공통 로그인과 검증된 관리자 권한을 사용한다.
- 현재 DB/자동 수집 목록, 전체 편집과 외부 검색, 숙련도, 삭제/복원, 자동 수집 검토는 유지한다.
- 공개 안내와 영상 용도는 기존 관리자 RLS의 songbook_entries에 부가 필드로 저장한다. 기존 데이터 일괄 갱신/신청 가능 일괄 설정은 하지 않는다.
- 자동 가창 링크는 수동 영상으로 복제하지 않고 기존 자동 수집 검토로 관리한다.
- 기존/신규 단위 검사, 격리 SQL 권한/호환성 검사와 실제 운영 모드 브라우저 검사 후 develop→main PR/기존 Actions 배포.

## 복구
운영 활성화 전 보고서의 직전 릴리스 정보를 보관한다. 코드 복구는 backup_20261007을 기준으로 새 PR/릴리스를 만들어 진행한다(강제 덮어쓰기 금지). 부가 DB 필드는 이전 코드와 호환되므로 복구를 위해 DROP하거나 데이터 삭제하지 않는다. 기존 배포의 라우팅 복구 자료는 Actions artifact에서 확인한다.
