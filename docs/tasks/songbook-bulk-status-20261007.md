# 노래책 선택 곡 상태 일괄 변경 / 페이지당 표시 수

## 범위
현재 운영 `3930cb8e` 기준. 원래 `backup_20261007` (`bc1cea3e`)는 그대로 보존한다.
기존 GitHub Actions를 사용해 develop 검증 후 main PR/운영 배포한다.

## 사용 흐름
- 일반/관리자 모두 목록 표 바로 위 우측에서 10/25/50/100곡씩 선택. 기본25.
- 페이지당 값은 perPage URL에 보관하고 새로고침에도 유지한다. 값 변경은 첫 페이지로 이동하며 검색은 유지한다.
- 관리자에게만 각 곡 앞 체크박스, 현재 페이지 전체 선택, 선택 수, 변경 상태, 실행 버튼.
- 상태는 기존 available/unreviewed/unavailable만 허용. 확인창에서 대상 곡명과 상태를 확인해야 저장한다.
- 현재 페이지 밖 곡을 암묵적으로 선택하지 않는다. 페이지/필터/정렬 변경과 로그아웃 시 선택은 해제한다.
- 같은 상태는 쓰기 없이 건너뛰며 완료/같은 상태/미처리 건수를 구분한다. 실패한 곡은 표시하고 자동 재시도하지 않는다.

## 저장/보호
기존 공통 로그인·서버 관리자 확인·RLS 유지. 기존 행은 id+request_status만 revision 조건부 PATCH한다.
정적/자동 목록에만 있는 곡은 현재 표시 정보의 최초 수동 override 행을 만들되 자동 가창 링크를 복제하지 않는다.
동일 곡명이 존재해도 상태만 바꾸는 작업을 일반 추가의 중복 검사로 차단하지 않는다.
최대100개를 순서대로 처리하고 작업 중 다른 편집을 잠근다. 계정/권한 변경 시 남은 요청을 보내지 않는다.
트랜잭션 원자성을 보장하는 기능은 아니며 일부 실패를 명확히 보여준다. 성공한 곡을 자동 원복하지 않는다.
기존 제목·가수·카테고리·별칭·영상·난이도·숙련도·메모·영상용도는 보존한다. DB 스키마 변경 불필요.
실제 운영 곡의 상태를 이번 배포 검증용으로 변경하지 않는다. 수집·일배치 스케줄/키 변경 없음.

## 검증
Node 단위검사: 유효 페이지 수/경계, 부분 PATCH, 새 override의 자동 링크 분리, 선택 제한, 부분 실패/권한 변경.
새 운영 경로 모의 브라우저 검사: 106곡 데이터, 기본값/모든 표시 수, 선택/취소/확인/같은 상태,
100곡 처리 및 페이지 밖 보존, 실패/충돌, 필터 후 빈 페이지, 관리자/일반회원, 반응형 배치.
기존101개 브라우저 그룹 유지. 운영 읽기 전용 검사에 표시 수 변경/새로고침/권한 UI/배치를 추가한다.

## 이어서 진행한 배포 전 점검
기존 구현의 PR #102 Actions 결과와 정확한 소스/검증 아티팩트를 다시 확인했다.
시각적 점검에서 모바일 일괄 변경 버튼이 세로로 과도하게 줄바꿈되는 것을 발견하여,
모바일 도구 영역을 선택/상태/실행 행으로 나눴다. 새 모바일 검사는 320/390px에서
실행 버튼 너비·한 줄 높이·상태 선택 아래 배치·텍스트 잘림 부재를 함께 확인한다.
실제 곡 상태를 테스트용으로 바꾸지 않고 기존 Actions의 격리 검사와 운영 읽기 검사를 사용한다.
