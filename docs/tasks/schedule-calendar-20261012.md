# 2026-10-12 일정 배치 calendar_layout_changed 복구

## 요청과 원인
사용자가 12시 실패 배치의 상태 확인 및 재실행을 요청했다. 운영 run 82(12:00), 83(12:03)는 calendar_layout_changed로 종료했고 변경 건수는 모두 0이다. 기존 함수를 dry-run으로 다시 호출해 HTTP 422를 재현했다.
연결된 원본 시트의 2026.9/2026.10/2026.11 B1:N32를 읽기 전용으로 대조했다. 11월은 1일이 일요일이지만 첫 주에 10월 25~31일이 있고 둘째 주부터 11월 1~7일이 나온다. 기존 파서는 11월 1일 시작만 예상하여 전체 3개월 수집을 중단했다. 원본 편집 오류나 통신 장애로 단정하지 않는다.

## 제한된 수정
calendar-grid.mjs는 기존 일요일 시작 방식과, 1일이 일요일인 달에만 전월 한 주를 포함하는 방식 두 개를 허용한다. 6주 42칸 모두의 날짜 순서와 해당 월 전체 포함 여부가 일치해야 한다. 임의 이동, 누락된 주, 잘못된 날짜는 계속 차단한다. 제목/분류, 전후월 제외, 변경 60건/삭제 15건 제한, 수동 일정/수정 우선권, 제외 목록, 토큰 인증, 메모 동기화는 바꾸지 않는다.
Google Sheet, cron 예약, 모니터 함수, 팬아트·영상·쇼츠·노래책 함수, 사용자 데이터는 수정하지 않는다.

## 검증 및 운영 절차
1. 로컬 달력 회귀 테스트와 GitHub Actions의 Verify, Develop promotion, Schedule calendar verification 검사.

3. 변경 없는 dry-run에서 3개월 파싱, 변경 건수와 메모 상태 확인 후 운영 배치 재실행.
4. 재실행 결과, 원본 대비 잔여 변경 0건, 수동 데이터 보호를 확인하고 실제 결과만 PR에 기록.
과거 12시 실패 기록은 성공으로 수정하지 않고 재실행을 별도 이력으로 남긴다.
